## What was built
| `--video_arch` | Implementation | Backbones |
|---|---|---|
| `frame_pool` | G5: pools embeddings, then the head classifies. Old checkpoints are detected by the missing `pool_format` key and keep logit pooling. | any 2D, `siglip` |
| `single_frame` | From Phase 2, kept | any 2D, `siglip` |
| `late_fusion` | First and last frames, concatenated, FC merge | any 2D, `siglip` |
| `early_fusion` | First convolution inflated to 3T channels | ResNet family |
| `slow_fusion` | Selects a native 3D model, default `r2plus1d_18` | native 3D |
| `tsm` | Shift inside the residual branch, no extra parameters, 2D names unchanged | ResNet family |
| `cnn_rnn` | LSTM or GRU over frame features | any 2D, `siglip` |
| `temporal_transformer` | CLS token, learned positions starting from sinusoidal | any 2D, `siglip` |
| `two_stream` | Middle RGB frame + L stacked motion fields, `--fusion avg\|fc`, `--motion_source farneback\|mv`, disk cache, `extract_embed='separate'` | ResNet family |

- **SigLIP** is a frame backbone for train, eval and embed (`--model_version siglip`, also with `--use-peft`), from the command line only.
- **Records.** The architecture is stored as a spec in `pooling`, for example `tsm:tsm_fold_div=8`. `build_video_model` parses it, so trainers, evaluators, embedding, `infer.py` and the desktop Test page needed no special cases. Runs recorded before this phase parse as before.
- **`flow_probe` bug:** confirmed fixed in the uncommitted diff. Periodic and speed use the flow summary; direction and scene_bias keep the mean flow. New test `test_flow_probe_separates_periodic` (at least 0.9 at 60 training clips).
- **Interfaces:** board entry I-010.

## Bugs found while reviewing the earlier work (fixed, with tests)
1. **Embedding pooling crashed on DenseNet with `added_layers=1`.** Its `extract_embed=True` returned logits, contrary to its docstring. Fixed in `src/vision/densenet.py` and `densenet_peft.py`. **This changes video embeddings:** with one added layer they go from `(B, classes)` to `(B, 1024)` on the dummy DenseNet, the features and not the logits. Weights and predictions are unchanged. The images modality is not affected: its embedder still refuses `added_layers` below 2 on DenseNet (`embed/vision/embed.py`). An earlier version of this report said images changed, which was wrong (V-046 item 5).
2. **SigLIP resize had no antialiasing,** unlike the PIL resize in its image processor. A shrunk frame differed from what the model expects. Now checked against PIL.
3. **The benchmark runner sent `mean:siglip` through the ImageNet transform.** It now uses SigLIP's preprocessing.
4. **`--motion_length` above the clip's frames, and `--tsm_fold_div 1`,** are now refused when the model is built.

### How far to trust these numbers
- **The table is one seed.** Thresholds (0.85, 0.62, 0.25) are not pre-registered; I inherited them with the earlier work and did not change them. The V-046 fix round below measures three models over more seeds. The others remain one seed.
- **The tiny backbone's 2x2 grid is not shown to help.** An earlier version of this report and of the backbone's docstring said it let `cnn_rnn` learn from 240 clips. That was a lucky seed; see the fix round. Real ResNets are still unmeasured, so **these results may change on the GPU.**
- **`late_fusion` does not pass the default direction task, and cannot.** See the fix round.
- **`temporal_transformer` has a changed start and tuned settings.** The earlier run moved it to normalised tokens and sinusoidal starting positions after near-chance results (0.575 at 240 and 800 clips), with `tt_dim=64` and lr 3e-4. These were chosen by looking at the held-out set.
- **Shuffled frames:** the assertion is on the mean of three orders. Single orders can stay high (0.825).

"Each motion-aware architecture can learn direction, with reversal and frame-order behaviour consistent with using motion, and appearance controls stay at chance across seeds. This is wiring evidence on an untrained tiny backbone with budgets tuned on the held-out set."

This must not be read as every model reliably beating chance. `late_fusion` does so only on the half-speed task, and several models fail on some seeds; the tables below give the rates. The user reworded Phase 3's done-when to this claim, in `PLAN.md` on `video-analysis`.

What these show:
- **`cnn_rnn`:** 2 of 10 runs pass from 240 clips, 9 of 10 from 800. The 1.000 at 240 clips was seed 0. The 2x2 grid is not shown to help: 800 clips give 4/5 with it and 5/5 with a global pool on dataset 0, and 5 seeds cannot separate those. The 240-clip case in `test_rgb_motion_models_beat_chance_and_depend_on_frame_order` stays as it was and still passes, but only because it uses seed 0.
- **`temporal_transformer` learns direction in only some runs.** 5 of 10 runs pass, and the failed ones sit at 0.50-0.625 with training accuracy at 0.91-0.99, so they memorise. I did not tune further. `test_temporal_transformer_beats_chance_given_enough_clips` uses a passing seed and does not show that the model learns reliably.
- **`late_fusion`, half speed:** 7 of 10 runs pass, so `test_late_fusion_beats_chance_when_two_frames_can_decide` also rests on a passing seed. The failed runs sit at 0.49-0.495.
- **`late_fusion`, default speed: it cannot pass, so it learns direction only on the half-speed task.** The first and last sampled frames are 11 frames apart, so a blob moves right by 11-22 px or left by 10-21 px, and modulo 32 these give the same horizontal displacement for most clips. The Bayes limit from horizontal displacement alone is 6/11 = 0.545. The vertical drift scales with speed, so it says a little more, and the limit from both is **about 0.663**, exactly (32 - 64 ln(21/16)) / 22. This replaces V-046's 0.548, which V-051 corrects. Both figures are far below 0.85. `test_two_frames_on_the_torus_have_a_bayes_limit_below_the_threshold` asserts the closed form, derived by hand, takes the frame span from the real sampler, and checks that the implied rule scores near the limit on 400 real tracks. That check shows the limit can be achieved and cannot catch an underestimate. The limit assumes that (dx, dy) holds everything the two frames say about the class, which is not tested, and it assumes exact blob positions and ignores codec artefacts. Measured runs reach at most 0.585, so the model is below the limit too.
- **Seed 0 flatters.** It passed every run above except `cnn_rnn` with a global pool at 240 clips and `late_fusion` at default speed. It also passed every motion row in the V-051 table below. Failure seems to follow the model seed more than the dataset: seed 3 failed 5 of its 6 runs in the 800-clip `cnn_rnn` (2x2), `temporal_transformer` and half-speed `late_fusion` rows. Two datasets are too few to state this firmly.

**Intervals.** Exact 95 % intervals on the pass rates: 9/10 is 0.55-1.00, 7/10 is 0.35-0.93, 5/10 is 0.19-0.81, 2/10 is 0.03-0.56. Runs share model seeds across the two datasets, so the effective sample is smaller than 10 and these intervals are, if anything, too narrow.

**Tests.** `test_some_model_seed_passes_the_oracle` (marker `seed_study`) reruns five seeds on dataset 0 and asserts that at least one passes. It checks wiring and is not a rate claim; the rates live here and in the script. The check scripts deselect it. The seed-0 slow oracles stay in CI, because `late_fusion`, `temporal_transformer` and `slow_fusion` have no other oracle there. To run it (about 9 minutes on CPU, not on a schedule):
