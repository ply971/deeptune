# B3: evaluation suite, df-analyze export, parity gaps

Branch `video/B3-evaluation`. Everything here ran on the CPU with tiny synthetic clips and `dummy_video3d` or stand-in models. **No number in this report describes a real model on real data.**

## What was done

**Validation (`evaluators/video/validation.py`, `run_validation.py`).** `--validation holdout|kfold|bootstrap632`, `--k`, `--n_boot`, `--keep_fold_models`.
- k-fold is stratified, and grouped (`StratifiedGroupKFold`, or `GroupKFold` for regression) when a group column exists.
- .632+ draws whole groups (P-117). The formula follows Efron & Tibshirani 1997, and is tested against a hand-worked example.
- Each model is a real `train` + `evaluate` call on its own subset files. 10% of its fit rows, whole groups, become validation, so the scored rows stay out of sample even when validation selects the checkpoint.
- Output: `cv_summary.json`, `fold_metrics.csv`, `assignments.csv`, `oof_predictions.csv`, `error_model_oof.json`, `error_calibration_oof.*`.
- `run_video_validation` only receives the train and validation files. The e2e test reads each fold's data and asserts that no test video is in it.

**Report (`evaluators/video/report.py`, `evaluators/calibration.py`, `evaluators/stats.py`).** Metrics are checked against scikit-learn. Video runs through `deeptune.py` now write `evaluation_report.json`, CSV tables and PNGs by default. `--report_boot` sets the resamples, and 0 turns it off.

**Calibration.** ECE, Brier, NLL and a reliability diagram, before and after. In a one-call run, the temperature is fitted on a second scoring pass over the validation split. `calibration_report` refuses a fit split named like the evaluation split. In k-fold, each fold's rows are scored with a temperature fitted on the other folds.

**Localisation (`evaluators/video/localization_report.py`).** mAP at tIoU 0.1 to 0.9, with averages over 0.1-0.5, 0.1-0.7 and all, per-class AP, classification mAP, boundary error, and a CLI. It agrees with a copy of CtxPL's `compute_average_precision_detection` on hand-made and 25 random tables, including duplicates, videos without ground truth, empty predictions, touching segments and tied scores.

**Uncertainty as an error estimate.** `validate_uncertainty`, `validate_segment_uncertainty`, `validate_video_uncertainty`: stated against observed per decile, separating `calibrated` from the weaker `ranks_errors`. `attach_expected_error` only adds the column when the check found it calibrated, and refuses when both splits are named and are the same.

**df-analyze export (`handlers/dfanalyze_export.py`, `embed/video/dfanalyze.py`).** `--export_dfanalyze`, `--dfanalyze_extras tta motion ids`, `--dfanalyze_clips`, `--dfanalyze_dims`, `--dfanalyze_rows`, from `deeptune.py` and from `embed/video/embed.py` (with `--dfanalyze_train_df`, `--dfanalyze_val_df`). The command is in `dfanalyze_export.json` and the README.

## Decisions

1. **`dfanalyze.csv` holds test rows by default.** df-analyze makes its own 60/40 split. On rows the model trained on, its holdout would read too high. Upstream DeepTune embeds the test split too. `--dfanalyze_rows all` exists and warns, unless the model is pretrained. These rows also fed DeepTune's own report, so a df-analyze result on them is further analysis of the same rows, not a second untouched test.
2. **Group ids stay out of the CSV by default, which has a cost.** With groups and no `ids`, df-analyze's split can put clips of one group on both sides. The export warns and tells the user to add `ids`, and the command then passes `--grouper group --drops split,video_id`.
3. **PCA per block.** With `tta`, means and standard deviations each get their own N components, both fitted on training rows. Motion statistics are not reduced. A request above what the training rows allow is capped, recorded and warned about, since this step comes after a long training.
4. **Same sampling on every split.** Training rows are embedded with `train=False` and no augmentation, including under `--video_augment`. This is tested.
5. **Motion statistics always use `framediff`.** `auto` can pick codec vectors for one video and frame differences for another, which would change a column's units between rows.
6. **Same seed on each fold** under `--fixed-seed`, matching "same config". Fold spread then leaves out initialisation. A separate seed per fold would be a later choice.
7. **The report runs last in `deeptune.py`,** after the tables are printed, and without a try/except, so a fault in it shows as an error but costs no earlier output.
8. **Fold weights and data subsets are deleted by default.** `--n_boot 50` would otherwise store 51 models. Clip-bytes datasets write each fold's subset to disk, and it is removed after the fold.

## What each interval covers

- `report.intervals`: which test units were drawn, one fitted model. Not training variability.
- `cv_summary.out_of_fold.intervals`: which units were drawn, pooled over fold models. It treats the pooled predictions as fixed, so it does not add training variability either.
- `cv_summary.across_folds`: spread between folds. Its t interval is too narrow because folds share data (Bengio & Grandvalet 2004), and the file says so.
- Paired `compare`: the difference between two fitted models on one test set. Not a p-value, and no correction for many comparisons.

## Open problems

- **Error model features.** Task 4 of the Phase 5 prompt lists clip disagreement and optional embedding distance as inputs. A4's `prediction_features(extra=...)` has the hook, but neither the trainer's fit nor the new out-of-fold fit passes them, so both use probability features only. Wiring it touches `Trainer` and `TestTrainer`. I left this open rather than change them late.
- **The temperature is not applied at inference.** It is reported only.
- **`.632+` with groups:** the formula's derivation assumes independent units. Resampling groups fixes the leakage, but the 0.632 weight is an approximation here, more so with groups of unequal size. The 0-1 loss is still per clip.
- **Small validation splits make the temperature unstable.** `n_fit` is reported, with no interval on it.
- **`--grouper` in df-analyze:** its docs do not say whether the column is removed from the features. The README tells users to check.
- **GUI:** the Results page does not show the new report or take these flags. Old runs read as before (tested). Phase 7 work.
- **Evidential uncertainty** has only run on synthetic arrays, because CtxPL outputs do not exist on this branch. Whether it is calibrated on real outputs is unknown.
- **Reference check:** the oracle in `test_localization_report.py` was copied by the previous B3 agent. This session I compared its logic with the repository's `eval_detection.py` through a summary of the fetched file (the tool limits quoting), not line by line.
- Pre-existing, left alone: `--use_case` help says `pretrained` is the default, but omitting it raises an error.

Check in those results: the strong model's interval lies above the single-frame one, the single-frame model is near chance, temperature scaling does not worsen ECE on test by much, and `error_calibration_oof.csv` follows the diagonal.
