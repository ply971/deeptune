# G1: the GUI catch-up

Branch `video/G1-gui-catchup`, on top of `video-analysis` eaf903f (R3b merged). The user's rule (PLAN.md 4b, 2026-11-03):
every user-facing feature that has landed is usable from the desktop app, and a GUI coverage test enforces it. Everything
here ran on the CPU with headless Dear PyGui contexts; no viewport was opened and no model was trained.

## What it adds

**One spec per flag.** `desktop/cli_options.py` declares a GUI control (`Opt`: kind, label, help, section, CLI default)
for each flag of `deeptune.py`, `infer.py`, `select_model.py`, `ensemble.py`, `extract_features.py`,
`train_feature_head.py` and `track.py` that had no control yet. The same spec drives the widget
(`desktop/option_widgets.py`), the stored value (saved with the settings) and the argv (`options_argv`). A flag is sent
only when its value differs from the CLI default, so the common path sends exactly the flags it sent before G1 (tested),
and a default the CLI refuses for some models is never sent (the R1 lesson; every GUI video model with default settings
is parsed by the real CLI in a test).

**Model & Training page.** The video model list now holds the pretrained Hugging Face backbones (V-JEPA 2, VideoMAE,
VideoMAE V2, SigLIP, SigLIP 2, DINOv3) with a note on the weights' licence, memory and default recipe; a clip model
fixes its frame count and greys out frame pooling. Pooling gains `single_frame`. **Advanced settings** holds every other
`deeptune.py` flag in eight collapsible sections, hidden when they do not apply to the modality:

| Section | Flags |
|---|---|
| Temporal architecture | `--video_arch` and its 14 option flags (TSM, CNN+RNN, temporal transformer, two-stream, probes) |
| Pretrained backbone and LoRA | `--unfreeze_backbone`, `--accept_weights_licence` (one box per opt-in licence, never pre-ticked), `--lora_rank` |
| Video data and decoding | decoder, sampling, stride, window, motion source, workers, frame cache and resize, clip storage |
| Augmentation | `--video_augment`, `--video_flip`, `--video_speed_perturb`, `--mixup_alpha`, `--cutmix_alpha`, `--mix_prob`, `--label_smoothing` |
| Training recipe | all T1 flags (precision, seed, checkpoints, resume, best epoch, early stopping, schedules, accumulation, BatchNorm, layer decay, EMA, logger) and `--config` |
| Evaluation and validation | `--test_clips`, `--test_crops`, `--validation`, `--k`, `--n_boot`, `--keep_fold_models`, `--cv_only`, `--test_df`, `--report_boot`, `--no_error_model` |
| Not sure (abstention) | `--target_error`, `--abstain_delta`, `--abstain_guarantee`, `--abstain_score`, `--calib_fraction` |
| df-analyze export | `--export_dfanalyze`, `--dfanalyze_extras`, `--dfanalyze_clips`, `--dfanalyze_dims`, `--dfanalyze_rows` |

`desktop/config.validate_run` (validate_config plus `options_issues`) explains the refused combinations before a process
starts: opt-in weights without their licence ticked, a flip without augmentation, cross-validate-only with holdout, a
frame pooling or a non-probe architecture on a clip model, train-the-whole-encoder on a model that is not frozen by
default, regression with mixup, unreadable numbers. `deeptune.py`'s own `validate_config` is unchanged: a CLI-built
config holds no GUI options, so a licence named on the command line is not refused twice.

**Test page (`infer.py`).** Batch size, "Answer every clip" (`--no_abstain`), the licence boxes, an ensemble (two or more
runs, one per line, plus "Allow unverified class indices"), and **Advanced: override what the run recorded**: every
other `infer.py` flag, blank by default (= the run's record), replacing one recorded value for this test only. The
override replaces the flag in the recorded argv rather than adding a second copy, and choosing another run clears the
overrides. With an ensemble the page sends only the flags `infer.py` accepts with `--ensemble`.

**New pages.** *Model Selection* (`select_model.py`, all 54 flags): **Check grid and estimate** runs `--dry_run` and shows
the counts and the time estimate in the log; **Start search** is enabled only after a dry run of exactly the current
settings passed (any change needs a new check). Rerunning into the same folder resumes and the page says so; the resume
flags are under Limits. Results lead with the **sealed-test score, labelled the honest number**, then the winner, the
reason, notes and the cross-validation leaderboard (`selection.json`, `leaderboard.csv`). *Ensemble* (`ensemble.py`):
runs (with "Fill runs from the output folder") or predictions tables; shows `ensemble.json`, metrics and predictions.
*Features & Probes*: `extract_features.py` and `train_feature_head.py`, each with its launch and reproducible command;
shows the feature folder and the probe metrics.

**Analyse Video page.** "More tracking options" reaches the 15 `track.py` flags the page lacked, including a whole
folder of videos (`--video_dir`; the page then shows the log and the output folder, not one overlay) and every
threshold (a value there replaces what the score threshold chose).

**Results shown from disk (torch-free, `desktop/tools.py`).** Results page: *Evaluation reports* with the test report and
its intervals, the k-fold / bootstrap .632+ summary, the abstention report (coverage, error among answered clips, status,
whether the guarantee holds, headline) and the df-analyze command. Test page: the abstention summary and the ensemble
record. Selection, ensemble and probe results on their pages.

**Device.** No training script has a device flag (they take CUDA whenever torch sees it). The sidebar's Device
(`auto`, `cpu`, `cuda:0`, `cuda:1`) sets `CUDA_VISIBLE_DEVICES` for every run started from the app (`cpu` = `-1`, the switch
CLAUDE.md documents), records it in `desktop-run.json`, and is a session setting, not saved in settings files. `track.py`'s
own `--device` is under More tracking options too.

**Plumbing.** `DeepTuneVisionOptions.build_parser(run_type)` and `deeptune.build_parser()` build the parser without
parsing, seeding or printing; `__init__` was split into `_build_parser` and `_read_parsed_args` with no change in
behaviour. `runner.start_tool_run` launches the four scripts like the others (cancellable, streamed log); a frozen build
runs them through `--tool-worker <name>` (`desktop/app.py`, hidden imports in `packaging/deeptune.spec`).

## The coverage test (`tests/test_gui_coverage.py`)

For every flag of the seven real parsers (the list comes from the parsers, not the GUI), the test finds the GUI control,
sets it to a value that differs from both the control's and the CLI's default (chosen per kind and checked against the
flag's own `type`/`choices`), runs the builder the GUI calls (`build_argv`, `build_infer_argv`, `build_tool_argv`,
`build_track_argv`) in the settings where the flag applies (video, images, GANDALF, TabPFN, DeepAR; ensemble on or off;
runs or predictions), and parses the argv with the real parser. The flag must be in the argv and parse back to the value
set. Controls that predate G1 (RunConfig, InferenceConfig, TrackConfig fields) have an explicit binding with their own
value and expected parse. Further tests: every spec control is a real widget whose value reads back (headless UI); the
field-bound controls exist as widgets; spec defaults and choices equal the CLI's; the GUI's copies of the strategy,
augmentation, metric, architecture and licence lists equal their sources; building the whole UI, visiting every page and
modality, imports no torch, torchvision or transformers (subprocess); and a non-vacuity test (a dropped flag and a wrong
expected value are both caught).

**Allow-list: empty.** Only argparse's own `-h/--help` is outside the count. The test caps the allow-list at 10 entries and
requires a reason of more than 20 characters for each.

**Mutation proof.** (1) Removing `--use-peft` from `build_argv`: `1 failed, 13 passed` (`deeptune.py: 1 flag(s) not
reachable from the GUI: {'--use-peft': 'not in argv; ...'}`). (2) Removing `--save_video` from `build_track_argv`:
`1 failed, 13 passed` (`track.py: ... {'--save_video': 'not in argv'}`). Both restored.

## Deviations and decisions

- **Hub backbones are a separate GUI list.** `tests/models/test_hub_backbones.py::test_desktop_config_accepts_the_command_line_models`
  asserts that no hub backbone is in `MODEL_VERSIONS_BY_MODALITY['video']` ("the GUI list is Phase 7"). G1's scope puts
  them in the GUI, so they are offered through `GUI_MODEL_VERSIONS['video']` (the torchvision list plus
  `VIDEO_HUB_MODEL_VERSIONS`), which the model combo and `load_config` use. The test was not changed and still passes,
  but its message is now out of date: **the coordinator should decide whether to reword it.**
- **Pre-G1 defaults kept.** The GUI still sends `--fixed-seed`, `--added_layers 2` and `--embed_size 1000` by default, as
  before G1 (the CLI defaults differ). Changing them would change every GUI run; the defaults test covers the G1 specs.
- **Override controls start blank** on the Test page (blank = the run's record), not at the CLI default, by design.
- **`--dry_run` is a button** (Check grid and estimate), not a checkbox; `--estimate_only` is a checkbox.
- **The Test page's ensemble lists every member**, the selected run included if wanted, so what is averaged is visible.
- **Device is a session setting** applied through `CUDA_VISIBLE_DEVICES`, as no training script has a device flag.

## Not done

- No viewport was opened: the layout, wrapping and scrolling of the new sections and pages were not looked at on screen,
  and `desktop\app.py --self-test` was not run (it trains). Someone should click through the three new pages once.
- No real-data run from the GUI (professional-quality rule 1): a GUI-launched video run with advanced settings, a
  dry run and a short search, an ensemble and a feature extraction should each be tried once on the GPU.
- GUI checks catch the common mistakes only; ranges of every numeric field are left to the CLI, whose refusal then
  shows in the log.
- The full suite was not run (instruction: targeted files only).
