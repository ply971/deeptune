## Decisions

- **The licence check sits in the loader.** `load_hub_model` calls `require_weights_choice`, so `deeptune.py`, `infer.py`, `extract_features.py`, `ensemble.py` and direct library use all pass through it. Acceptance is process state, set by each entry point from its flag, which avoided threading a new argument through every caller of `build_video_model`. Ensemble members are the exception: each is checked and loaded with only its own record plus the flag. A run that recorded its acceptance rebuilds without being asked again; that assumes the same person, or someone who has read the record.
- **Naming the licence, not a yes flag.** The flag takes the licence id, so accepting `MIT` or a different licence does not unlock CC-BY-NC weights. This records a choice. It does not enforce the terms.
- **VideoMAE does not use `from_pretrained`.** `transformers` 5.16.1 has `query.bias` and `value.bias` on its attention layers and no conversion for the older `q_bias`/`v_bias` names (read in `models/videomae` and `conversion_mapping.py`, no match). If a file has the old names, `from_pretrained` would leave those biases at their start with only a warning. So DeepTune reads the raw file, converts the keys and loads strictly. Whether `MCG-NJU/videomae-base` really has the old names was **not checked**, because that needs the file; the converter handles both.
- **VideoMAE V2 without remote code.** Its repository needs `trust_remote_code`, which P-115's reasoning rules out. The converter maps upstream names, taken from `modeling_videomaev2.py` on its Hugging Face page, to the native model, and the config values come from that repository's `config.json`. Tested only on a synthetic file packed in that layout. **`_upstream_v2_layout` in the tests is the inverse of my own converter, written from the same reading of the upstream code, so those tests show the two agree with each other and cannot show the upstream key names are right. Only the real-weights gate can check them**, and a strict-load failure there would be the first sign of anything I misread.
- **A partial load is an error.** `checked_from_pretrained` raises on missing or mismatched keys. `transformers` would only warn and keep random weights.
- **V-JEPA 2 only accepts its configured size.** Its RoPE computes each token's position from its index and the configured grid, so another size would run and give scrambled positions. `encoder_token_grid` refuses it. Frame counts are free: `T' = T // 2`, a last odd frame is dropped, and one frame is repeated.
- **V-JEPA 2's predictor is dropped.** It only serves self-supervised training, and dropping it saves memory and checkpoint size.
- **SigLIP 2 loads through `SiglipModel`, and resizes bilinearly.** `google/siglip2-base-patch16-224/config.json` says `model_type: siglip`, and its `preprocessor_config.json` says resample 2, unlike SigLIP v1's bicubic (3). Both files were read on the Hub. Reusing B2's bicubic would have been silently wrong.
- **Encoders are frozen by default in the CLI**, including `siglip2_b16` and `dinov3_vitb16` under P-101 (B2's `siglip` keeps its behaviour), with `--unfreeze_backbone` as the way out, and the run prints this. A frozen encoder runs in eval mode under `no_grad`. This is read at each call, so `--trainable_params` unfreezing part of it still trains.
- **The head comes from the pooling spec** (`attentive_probe:probe_depth=1,...`, `linear_probe`), as B2 did for architectures, so inference needs no new plumbing. `--added_layers` and `--embed_size` do not shape it. `embed_size` is the LoRA rank only when no rank is recorded. The default probe depth stays B1's 1, while the V-JEPA 2 evaluation protocol uses 4.
- **LoRA targets `query` and `value`, with gradient checkpointing on.** Both are called layers in both families, and `test_every_lora_adapter_gets_a_gradient_with_checkpointing_on` proves no adapter is dead (the V-040 failure).
- **Ensembles average probabilities, not logits.** A test has a case where the two disagree. The members' `expected_error` is dropped, since each error model describes one model. Always refused: different tasks, different class counts, recorded label mappings that differ, rows that do not match, different labels. A member whose mapping cannot be verified is refused unless `--allow_unverified_labels` is given, and then nothing checks its class order. See the V-052 round below; an earlier version of this line claimed more than the code did.
- **`--predictions` is the route for feature probes**, because `train_feature_head.py` has no pixel path (the rest of P-119). A pixel run and a probe cannot be mixed: their tables are keyed differently (`sample_id`, `video_id`).
- **DINOv3 stayed a thin wrapper**: one registry row and one branch for its class and register tokens, so it is built and not left as a note.
- **P-105 is not assumed.** Nothing here reads a leakage audit. `train_feature_head.py`'s own split audit is B1's.

Smaller items:

- **False accuracy.** Names with no mapping are no longer scored, in `predict_video` and in ensembles, and the run says why. Single-model scoring is otherwise unchanged. Labels other than whole numbers also count as not comparable when there is no mapping (for example `1.0`, which compared unequal to `1` before).
- **`pos_embed`.** A file holding position embeddings is refused rather than dropped. If a real file stores the fixed sin-cos table, this refuses it too, and the gate would show that.
- **Budget errors** on these models point to `--probe_width`, `--probe_depth` and `linear_probe`. Other models' messages are unchanged.
- **`--unfreeze_backbone`: refused**, not warned, on a model it would not affect and alongside `--freeze-backbone` or `--use-peft`.
- **`weights_revision`** is recorded next to `weights_licence`: the commit of the local Hugging Face snapshot. If it cannot be read (not in the cache, or a local folder) the record says `unknown: ...`, the run still goes ahead, and the weights can only be traced to their repository name. It is read when the record is written, not from the files that loaded, so a cache updated in between would mislead. `siglip` loads from `downloaded_models/` first, so its revision may be `unknown`, or the cache's while the folder's copy is what ran. Fixing that is not worth it while `siglip2_b16` is the recommended stream.
- **`inference_run.json`** from single-model `infer.py` (video) records the licence and revision.
- **One shape.** `weights_licence` is now a plain string in all single-model records, because existing B3 tests require that for pretrained embeddings. `train_feature_head.py` stays `{stream: text}`.
- **Crop rounding** now rounds down, matching the processors, in `HubClipTransform` and `crop_window`. Torchvision presets keep their own rounding.

Tests of mine that this round changed, all from this branch: `_save_run` now writes a mapping and its record; `_tiny_videomae` has non-zero biases; assertions moved from `{version: text}` to the plain string; the mapping-conflict test now also runs with the flag allowed; the DINOv3 and SigLIP 2 end-to-end cases no longer pass `--freeze-backbone`, so they cover the default. No test from before R1 changed.

**The regression crash** (`helpers.py`, commit `cdeee91`) was pre-existing and not R1's. `numbers.Number` replaced the first version's check in the round's main commit.

## Open problems and things not done

- **Real weights are unverified.** The processors were compared with the `transformers` classes on CPU, and shapes and key names checked with tiny models, but no real checkpoint has loaded. Key names of the two VideoMAE files are the largest risk.
- **`extract_features.py` runs in float32 with no autocast.** Under 8 GB this may be the first limit on V-JEPA 2. I did not add a flag I could not test on the GPU. If the gate shows it is too heavy, add bf16 there first.
- **`--test_crops` on these models:** T1's views resize back to the input size, so they run, but this was not tested here. Its numbers are not the Kinetics 3-crop protocol (T1 open problem 5).
- **Feature probes have no `infer.py` path or `expected_error`** (rest of P-119, unchanged).
- **Ensembles have no calibration or error estimate.** An average of probabilities need not be calibrated, and R2 would need to fit on the ensemble's own output.
- **Licence ids are read from model cards** (F-002, and the SigLIP card read 2026-10-31), not from a machine-readable check at load time. A later change to a card is not detected.
- **`siglip` still loads from `downloaded_models/`** like the images modality. `siglip2_b16` uses the Hugging Face cache.
- **GUI:** the new versions are command-line only, like SigLIP (Phase 7).
- **V-JEPA 2.1:** a note only. Reopen when its weights state a licence and `transformers` has a loader (P-115, F-015).

**Context only:** on this GPU, frozen `r3d_18` used about 650 MB under bf16 and full fine-tuning about 1.1 GB at batch 4. That is an 18-layer 3D CNN at 112 px and says nothing about a ViT-L at 256 px.
