## Decisions

- **The licence check sits in the loader.** `load_hub_model` calls `require_weights_choice`, so `deeptune.py`, `infer.py`, `extract_features.py`, `ensemble.py` and direct library use all pass through it. Acceptance is process state, set by each entry point from its flag, which avoided threading a new argument through every caller of `build_video_model`. A run that recorded its acceptance rebuilds without being asked again; that assumes the same person, or someone who has read the record.
- **Naming the licence, not a yes flag.** The flag takes the licence id, so accepting `MIT` or a different licence does not unlock CC-BY-NC weights. This records a choice. It does not enforce the terms.
- **VideoMAE does not use `from_pretrained`.** `transformers` 5.16.1 has `query.bias` and `value.bias` on its attention layers and no conversion for the older `q_bias`/`v_bias` names (read in `models/videomae` and `conversion_mapping.py`, no match). If a file has the old names, `from_pretrained` would leave those biases at their start with only a warning. So DeepTune reads the raw file, converts the keys and loads strictly. Whether `MCG-NJU/videomae-base` really has the old names was **not checked**, because that needs the file; the converter handles both.
- **VideoMAE V2 without remote code.** Its repository needs `trust_remote_code`, which P-115's reasoning rules out. The converter maps upstream names, taken from `modeling_videomaev2.py` on its Hugging Face page, to the native model, and the config values come from that repository's `config.json`. Tested only on a synthetic file packed in that layout, so a strict-load failure at the gate would be the first sign of anything I misread.
- **A partial load is an error.** `checked_from_pretrained` raises on missing or mismatched keys. `transformers` would only warn and keep random weights.
- **V-JEPA 2 only accepts its configured size.** Its RoPE computes each token's position from its index and the configured grid, so another size would run and give scrambled positions. `encoder_token_grid` refuses it. Frame counts are free: `T' = T // 2`, a last odd frame is dropped, and one frame is repeated.
- **V-JEPA 2's predictor is dropped.** It only serves self-supervised training, and dropping it saves memory and checkpoint size.
- **SigLIP 2 loads through `SiglipModel`, and resizes bilinearly.** `google/siglip2-base-patch16-224/config.json` says `model_type: siglip`, and its `preprocessor_config.json` says resample 2, unlike SigLIP v1's bicubic (3). Both files were read on the Hub. Reusing B2's bicubic would have been silently wrong.
- **Encoders are frozen by default in the CLI**, with `--unfreeze_backbone` as the way out, and the run prints this. A frozen encoder runs in eval mode under `no_grad`. This is read at each call, so `--trainable_params` unfreezing part of it still trains.
- **The head comes from the pooling spec** (`attentive_probe:probe_depth=1,...`, `linear_probe`), as B2 did for architectures, so inference needs no new plumbing. `--added_layers` and `--embed_size` do not shape it. `embed_size` is the LoRA rank only when no rank is recorded. The default probe depth stays B1's 1, while the V-JEPA 2 evaluation protocol uses 4.
- **LoRA targets `query` and `value`, with gradient checkpointing on.** Both are called layers in both families, and `test_every_lora_adapter_gets_a_gradient_with_checkpointing_on` proves no adapter is dead (the V-040 failure).
- **Ensembles average probabilities, not logits.** A test has a case where the two disagree. The members' `expected_error` is dropped, since each error model describes one model. Refused: different tasks, different class counts, differing label mappings, rows that do not match, different labels.
- **`--predictions` is the route for feature probes**, because `train_feature_head.py` has no pixel path (the rest of P-119). A pixel run and a probe cannot be mixed: their tables are keyed differently (`sample_id`, `video_id`).
- **DINOv3 stayed a thin wrapper**: one registry row and one branch for its class and register tokens, so it is built and not left as a note.
- **P-105 is not assumed.** Nothing here reads a leakage audit. `train_feature_head.py`'s own split audit is B1's.

## Open problems and things not done

- **Real weights are unverified.** The processors were compared with the `transformers` classes on CPU, and shapes and key names checked with tiny models, but no real checkpoint has loaded. Key names of the two VideoMAE files are the largest risk.
- **`extract_features.py` runs in float32 with no autocast.** Under 8 GB this may be the first limit on V-JEPA 2. I did not add a flag I could not test on the GPU. If the gate shows it is too heavy, add bf16 there first.
- **`--test_crops` on these models:** T1's views resize back to the input size, so they run, but this was not tested here. Its numbers are not the Kinetics 3-crop protocol (T1 open problem 5).
- **Feature probes have no `infer.py` path or `expected_error`** (rest of P-119, unchanged).
- **Ensembles have no calibration or error estimate.** An average of probabilities need not be calibrated, and R2 would need to fit on the ensemble's own output.
- **Licence ids are read from model cards** (F-002, and the SigLIP card read 2026-10-31), not from a machine-readable check at load time. A later change to a card is not detected.
- **`siglip` still loads from `downloaded_models/`** like the images modality. `siglip2_b16` uses the Hugging Face cache.
- **GUI:** the new versions are command-line only, like SigLIP (Phase 7).
- **V-JEPA 2.1:** a note only. Reopen when its weights state a licence and `transformers` has a loader (P-115, F-015).

## Not run on real data or the GPU: commands for the gate

Warn the user first, because heavy GPU runs have frozen this laptop. **The downloads need approval:** V-JEPA 2 and SigLIP 2 are not in the local cache. VideoMAE needs the licence accepted and is optional. DINOv3 needs Meta's approval and is optional.

**Context only:** on this GPU, frozen `r3d_18` used about 650 MB under bf16 and full fine-tuning about 1.1 GB at batch 4. That is an 18-layer 3D CNN at 112 px and says nothing about a ViT-L at 256 px.

```powershell
# 1. Loads, token grids, and peak memory of one frozen forward, at DeepTune's own frame counts
.venv\Scripts\python.exe scripts\smoke_modern_backbones.py --versions vjepa2_vitl siglip2_b16 --frames 8 16 --batch_size 1 --out .artifacts\r1_gate\smoke.json
.venv\Scripts\python.exe scripts\smoke_modern_backbones.py --versions vjepa2_vitl --frames 8 16 --batch_size 1 --precision fp32 --out .artifacts\r1_gate\smoke_fp32.json

# 2. The default recipe on a real subset, 8 and 16 frames (repeat with --snippet_frames 8). extract_features.py runs in float32
.venv\Scripts\python.exe extract_features.py --data clips.csv --out .artifacts\r1_gate\vjepa_16 --model_version vjepa2_vitl --snippet_frames 16 --cache_tokens 8x4x4 --batch_size 1
.venv\Scripts\python.exe train_feature_head.py --features .artifacts\r1_gate\vjepa_16 --train_df train.csv --val_df val.csv --test_df test.csv --out .artifacts\r1_gate\probe_vjepa_16 --num_classes <n> --fixed-seed

# 3. The appearance stream, on the same rows
.venv\Scripts\python.exe extract_features.py --data clips.csv --out .artifacts\r1_gate\siglip2_16 --model_version siglip2_b16 --snippet_frames 16 --cache_tokens 8x4x4 --batch_size 1
.venv\Scripts\python.exe train_feature_head.py --features .artifacts\r1_gate\siglip2_16 --train_df train.csv --val_df val.csv --test_df test.csv --out .artifacts\r1_gate\probe_siglip2_16 --num_classes <n> --fixed-seed

# 4. The two averaged, compared with each member on the same test rows
.venv\Scripts\python.exe ensemble.py --predictions .artifacts\r1_gate\probe_vjepa_16\predictions.csv .artifacts\r1_gate\probe_siglip2_16\predictions.csv --out .artifacts\r1_gate\ensemble

# 5. The pixel path once, for its peak memory (training_run.json), then a new process that knows only the checkpoint
.venv\Scripts\python.exe deeptune.py --modality video --df clips.csv --raw-data --out .artifacts\r1_gate\pixels --model_version vjepa2_vitl --num_frames 16 --batch_size 1 --precision bf16 --num_epochs 2
.venv\Scripts\python.exe infer.py --modality video --checkpoint <run>\trainval_output_*\model_weights.pth --data <video> --out .artifacts\r1_gate\infer --model_version vjepa2_vitl --num_classes <n>

# 6. Only if chosen: VideoMAE is non-commercial, and this is where its key conversion gets its first real test
.venv\Scripts\python.exe scripts\smoke_modern_backbones.py --versions videomae_b16 videomae_v2_b16 --frames 16 --accept_weights_licence CC-BY-NC-4.0
```
